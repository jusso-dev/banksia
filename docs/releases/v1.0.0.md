# Banksia 1.0.0

Released 23 November 2026.

Banksia is self-hosted backup for Microsoft 365. It backs up Exchange Online mailboxes and OneDrive to storage you own, restores items back into the tenant, and proves on a schedule that restores work.

## Highlights

- **Backup.** Incremental mailbox and OneDrive backups through Microsoft Graph, using a read-only app registration. Everything is encrypted on your host before it reaches Azure Blob, Cloudflare R2 or a local directory.
- **Restore.** Plan, review, approve by hash, then apply. Restores only add data: they go to a new `Banksia Restore/<plan id>` folder by default, never overwrite, and can be repeated safely.
- **Restore tests.** `banksia restore-test run` restores a sample to a throwaway mailbox and OneDrive, reads it back, compares it with the backup and writes a signed evidence pack for auditors.
- **Stable interfaces.** From 1.0, the command line, `banksia.toml`, repository format version 1, evidence pack format and exit codes follow semantic versioning.

Each archive contains the `banksia` binary, `README.md`, `LICENSE`, `CHANGELOG.md`, `banksia.example.toml` and `deploy/`. Check downloads against `SHA256SUMS`:

```sh
shasum -a 256 --check --ignore-missing SHA256SUMS
```

The macOS binary is not notarised. Remove the quarantine attribute after you check its hash: `xattr -d com.apple.quarantine banksia`.

## Install

1. Install the binary to `/usr/local/bin/banksia`.
2. Create the `banksia-backup` and `banksia-restore` app registrations and a throwaway restore-test user ([security.md](../security.md)).
3. Copy `banksia.example.toml` to `/etc/banksia/banksia.toml` and edit it. Secret values never go in this file.
4. `banksia key generate --out /etc/banksia/master.key`. Keep an offline copy: losing the key makes the repository unreadable.
5. `banksia repo init`, then `banksia backup run`.
6. Install the systemd timers or cron entries from `deploy/`.

The [README](../../README.md#quick-start) has the full quick start.

## Upgrading

No earlier release was published, so there is nothing to upgrade. If you ran a 0.1.0 build from source, it uses the same repository format (version 1) and configuration, and 1.0.0 reads it unchanged. See [upgrading.md](../upgrading.md).

## Required permissions

| App | Graph application permissions |
| --- | --- |
| `banksia-backup` | `Mail.Read`, `Files.Read.All`, `User.ReadBasic.All` |
| `banksia-restore` | `Mail.ReadWrite`, `Files.ReadWrite.All`, `User.ReadBasic.All` (scope mail and files to restore targets with Exchange RBAC for Applications and `Sites.Selected`) |

The storage identity needs create and read access only. Do not grant delete.

## Known limitations

- **Not yet proven on a production tenant.** 1.0 is tested end to end against an in-process fake of the Graph endpoints Banksia uses. Run the [opt-in live test](../testing.md#opt-in-live-test) against your own throwaway mailbox before you rely on Banksia, and keep another backup until restores are proven in your environment.
- **Mail restore fidelity.** Restored mail is imported as MIME through Graph v1.0. Exchange can mark it as a draft, and categories, flags and read state are not carried by MIME ([#10](https://github.com/jusso-dev/banksia/issues/10)).
- **OneNote notebooks** and other OneDrive packages are skipped.
- **Retention** is applied by storage immutability and lifecycle policies. Banksia never deletes and has no prune command.
- **Keys** cannot be rotated in place, and KMS wrapping is not built.
- **Approval** is a hash on the command line, not a signed approval from a second identity.
- **SharePoint, Teams and Entra ID** are not backed up yet ([#9](https://github.com/jusso-dev/banksia/issues/9)).

## Verification for this release

- `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test --workspace --locked`: 80 tests pass.
- `cargo audit`: no vulnerabilities. Two transitive dependencies of `object_store` (`chrono`, `humantime`) are flagged as unmaintained.
- Release archives were built with `scripts/release.sh` on macOS (Apple silicon). The macOS binary passed a smoke test (`key generate`, `repo init`, `repo info`, `snapshots list`, `audit list` against a local repository). The Linux binaries are statically linked and cross-compiled with Zig; they were not run before release.

## Security

Report vulnerabilities privately to the repository owner through GitHub. Do not open a public issue with exploit details. See [security.md](../security.md) and [threat-model.md](../threat-model.md).
